## 1. Цель и граница

**Цель.** За 72 часа непрерывной работы агентов превратить прототип в продукт, который можно открыть первым платящим пользователям. Все этапы пути трейдера должны работать минимально, но честно: вход → оплата → челлендж → риск → прохождение → funded → выплата.

**Принцип.** Работа идёт в **новом репозитории** `props-v2` (`/Users/dev/code/props-v2`). Текущий репозиторий `PROP-Solana` остаётся нетронутым эталоном и источником кода. В новый репозиторий переносится только проверенный код, остальное пишется заново. Стек тот же: Next.js 14, Prisma, TypeScript, слой рыночных данных из прототипа.

## 2. Архитектура v2

```
Браузер ──poll 2.5s──► Next.js API ──► слой рыночных данных (без изменений) ──► Phoenix API
   │                       │
   │  SIWS-вход, команды   ├── withAccountLock(accountId) ──► Postgres
   │                       │        └── core/position + core/risk (чистые функции, Decimal)
   │                       │
   └──────────────────── worker (отдельный процесс, тот же код)
                             ├── каждую 1 с: тик риска по всем открытым позициям
                             ├── каждые 15 с: проверка оплат Solana Pay
                             └── 00:00 UTC: смена торгового дня
```

Три решения, которые закрывают большую часть дефектов:

1. **Чистое ядро денег `src/lib/core/`.** Позиция, PnL, комиссии, ликвидация и риск считаются в чистых функциях на `Prisma.Decimal` без доступа к БД. API и воркер только вызывают их. Закрывает D1, D3, D4, D8, D9.
2. **Одна точка записи `withAccountLock`.** Любое изменение счёта идёт внутри `prisma.$transaction` с `pg_advisory_xact_lock` по идентификатору счёта. API и воркер не могут затереть друг друга. Закрывает D5.
3. **Воркер вместо браузера.** Отдельный процесс `src/worker/index.ts` исполняет лимитки, переоценивает позиции и меняет торговый день. Браузер перестаёт слать `CHECK_LIMIT_ORDERS`. Закрывает D2, D6.

### Модель позиции

Размер позиции хранится в **базовом активе**, а не в USD. Номинал считается как количество, умноженное на цену. Плечо определяет только требуемую маржу, на PnL оно не влияет.

```
quantity      = sizeUsd / fillPrice            (округление вниз по lotSize рынка)
notional      = quantity × markPrice
margin        = notional / leverage
unrealizedPnL = quantity × (mark − entry) × (LONG ? 1 : −1)
fee           = notional_fill × takerFee рынка  (из каталога Phoenix)
liquidation   = equity счёта < Σ margin × maintenanceRatio
```

### Изменения схемы Prisma

| Изменение | Зачем |
|---|---|
| `provider = "postgresql"`, все деньги и цены `Decimal` | D8 |
| `Position.quantity` — количество в базовом активе, плюс `margin` | D1 |
| Новая `LedgerEntry`: `accountId`, `type` (FEE, PNL, FUNDING, PAYOUT, ADJUST), `amount`, `refId` | Баланс равен сумме проводок |
| `Order.idempotencyKey` с уникальным индексом | Повтор команды не создаёт второй ордер |
| `TradingAccount.rulesHash`, `lastTradeDay`, `phase` (CHALLENGE, FUNDED_SIM) | Неизменность правил, учёт торговых дней, funded-стадия |
| `User.role`, новые `AuthNonce`, `Session` | D7 |
| Новые `Purchase` (reference, сумма, статус, подпись), `AuditLog`; расширенный `Payout` (подпись, одобривший) | Оплата, выплаты, аудит |

Поле `mode` и текущая политика режимов остаются: реальный FUNDED по-прежнему отвечает 503.

## 5. Критерии готовности

Версия считается готовой, только если выполнены все пункты.

**Инварианты денег** проверяются тестами и после нагрузочного прогона:
- баланс счёта равен сумме его проводок до цента;
- equity равна балансу плюс нереализованный PnL;
- PnL полного закрытия равен количеству, умноженному на изменение цены, минус комиссии, без умножения на плечо;
- частичное закрытие зачисляет пропорциональный PnL, флип закрывает старую позицию с PnL;
- повтор команды с тем же ключом не меняет состояние;
- после FAILED или PASSED новые позиции не открываются.

**Риск без участия человека:**
- пробой дневного или статического floor по equity закрывает позиции и переводит счёт в FAILED в течение 2 секунд;
- лимитки исполняются при закрытом браузере;
- торговый день меняется в 00:00 UTC сам.

**Безопасность:**
- ни одного обращения к `trader@project.io` в коде;
- каждый API, кроме публичных рыночных данных, требует сессию, админские — роль ADMIN;
- реальный FUNDED по-прежнему отвечает 503.

**Честность витрины:** в интерфейсе нет вымышленных чисел.

**Эксплуатация:** `docker compose up` поднимает систему с пустой базы. typecheck, тесты и сборка проходят.
